## At a glance

```js check=browser
import '@zoworkhq/zoforms/styles.css';
```

- **The stylesheet is optional.** Import it once, from your app's code. Without it the form is plain HTML with these classes.
- **Every public class, data attribute and custom property starts with `zf-`.** Properties that start with `--_zf-` are the stylesheet's own and not for you to set.
- **Every rule is wrapped in `:where()`,** so it has no specificity, and any plain rule of yours wins without `!important`.
- **`classNames`,** exported from `@zoworkhq/zoforms/react`, lists every class below.

[Style the form](/docs/integrate/styling) shows how to use them.

## Data attributes for your page

Put these on an element around the form, such as the wrapper you render it in, not on the form itself. After a submit, the form is replaced by the success message and scores, and attributes on the form don't carry over to them.

| Attribute | Values | Effect |
|---|---|---|
| `data-zf-theme` | `"dark"` | The dark theme. Opt-in only: it never follows the operating system's setting. |
| `data-zf-density` | `"patient"`, `"standard"` (default), `"dense"` | Control height, spacing and type size. The nearest ancestor with the attribute wins. |
| `data-zf-group-style` | `"box"` | Root-level groups in a light box, instead of the rule down their leading edge. |
| `data-zf-progress-style` | `"bar"`, `"caption"` | Overrides the author's progress style in a form with pages, either way. `"bar"` adds a segmented bar above "Step x of y". The caption always stays. |

The progress bar and boxed groups exist only in the stylesheet. Without it, those two attributes do nothing.

## Custom properties

Set them on the form or on any element around it, such as `:root` or a wrapper. They reach the form, and the success message and scores list shown after a submit. A value nearer the form wins. A value you set applies in both themes and every density.

Set them on the form or around it, never on an element inside it: the stylesheet reads them on the form, the success message and the scores list only.

An invalid value doesn't fall back to the default. The property is set, so the declarations that use it are invalid, and the browser uses their inherited or initial value instead: a Submit button with no background, for instance.
