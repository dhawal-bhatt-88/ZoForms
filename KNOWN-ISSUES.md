# Known issues

- **Pages have no `label`, but the AI service and the responses page read `block.label`.** A page is named by `title`. To keep those out-of-scope files compiling without changing them, `PageBlock.label` is typed as a required `never` in `packages/form-schema`, so `block.label` still types as `string`. At runtime `apps/api/src/ai/ai.service.ts` and the responses page get `undefined` for a page (for a paged form, that is every top-level block), with no compile error. Revisit when they come back into scope: read names with `blockName`, then change `PageBlock.label` to `label?: never` so the compiler flags any remaining reads. (Phase 7, pages.)
- **The builder's own submit check reads root answers only.** `validateSubmission` in `packages/form-schema` (used by the public submit endpoint behind `/r/<slug>`) loops over the form's root list. It never looks inside pages or groups, so nested questions aren't checked: their `required` is not enforced and their answers are dropped. Groups aren't in `STATIC_TYPES`, so a root-level repeating group's value, an array of instances (contract §12.4), would be stored without any check of its shape, instance count or contents. The `@yourco/forms` renderer validates and strips per instance itself; this gap is only in the builder's hosted form. Revisit when Responses and `/r/<slug>` come back into scope: walk the tree with `walkBlocks`, and validate repeating groups per instance as in contract §12.5. (Repeating groups.)
- **The AI features know coded options only well enough to keep working.** Options are `{ code, label }` (contract §13). `apps/api/src/ai/ai.service.ts` still asks the model for plain option labels; each one becomes `{ code: "", label }` and the parse generates its code (§13.3). For "Ask AI" edits the model is shown the form with its codes but answers with labels, so every option it returns gets a code generated afresh from its label. An option the author had given its own code (or a renamed label) comes back with a different code, and conditions using the old code then fail the save check. Translate sends the whole schema to the model, codes included, and nothing stops it translating them. Revisit when AI features come back into scope: have the tools return `{ code, label }` and keep the existing codes. (Coded options.)
- **The hosted form (`/r/<slug>`) stores codes, and nothing downstream shows labels.** `apps/web/src/app/r/[slug]/page.tsx` was changed only to compile against coded options: it shows labels and stores codes, as the renderer does (§13.4). `validateSubmission` doesn't check that a submitted value is a code of the list, and does not return labels the way `prepareSubmission` does (§13.5). The Responses and Analytics pages show the stored values, so they now show codes rather than labels. Revisit with Responses, Analytics and `/r/<slug>`. (Coded options.)
- **A code left invalid can lose track of its conditions.** When an option's code is changed, the conditions using it follow once the author leaves the field with a valid, unique code (contract §13.8). If the author leaves an invalid or clashing code, the editor remembers the code the conditions still use, by block, list and position (`codeOrigins` in `apps/web/src/components/form-editor/editor.tsx`), and they follow once it's fixed. Removing an option or importing into that block clears this memory, because positions shift. The conditions then stay on the old code. Nothing breaks silently: each one shows "the answer … isn't the code of any option" in its Logic section, and the save is refused until it's fixed. Revisit if authors hit it: give options a stable editor-only key instead of their position. (Coded options.)
- **The form editor isn't read-only for viewers.** A VIEWER can open any of the organisation's forms in the editor and change anything on the canvas and in the inspector — questions, logic, pages, settings, "Ask AI" — and the Save button is enabled. Only when they save does the API refuse, with 403 "Viewers have read-only access." (`assertCanEdit`), shown as "Couldn't save: …"; their edits stay on screen until they leave. The template actions are already hidden for viewers (the Team page's pattern: `useCanEdit`, write controls hidden rather than disabled), and a template opened by its address is read-only, but the form editor itself, "Generate with AI" on My forms and the form cards' menu (Duplicate, Delete) are not. Revisit: give the form editor a read-only mode for viewers (no Save or Cancel, inputs read-only, no insert menu or AI), and hide the other form write actions the same way. (Templates.)
- **The editor's existing dialogs don't return focus when they close.** The delete-group, delete-page and "Add pages" dialogs and the option import dialog move focus in when they open (`autoFocus`) and close on Escape, but when they close nothing puts focus back on the control that opened them, so a keyboard or screen reader user is left at the top of the page. The embed dialog does neither: focus stays behind it, and Escape doesn't close it. Revisit: on close, put focus back on the control that opened each one, and check each with a screen reader. (Templates.)
- **`verify-options.js`'s render step fails until the renderer's required-marker fix ships.** With the external-app variables set, "script ran without error" fails: `group("Priorities")` (`getByRole("group", { name: "Priorities", exact: true })`) times out. Since `@yourco/forms` 0.18.2 a ranking with `completeRequired` is marked required, and the marker is a CSS `::after " *"` on the legend, which Chromium counts in the accessible name, so the group is named "Priorities *". The test's exact name is correct; the renderer will be fixed to keep the marker out of the name. Rendered on 0.18.1, 0.20.0 and 0.21.2 (14 Oct 2026): 0.18.1 names it "Priorities"; 0.20.0 and 0.21.2 are identical, so the grid container-query change in 0.21.x isn't involved. The other steps in the suite pass, and without the external-app variables it passes in full. Revisit when the fixed renderer is installed in the test app: run `verify-options.js` with the variables set, then remove this entry. (Renderer.)
