# Known issues

- **Pages have no `label`, but the AI service and the responses page read `block.label`.** A page is named by `title`. To keep those out-of-scope files compiling without changing them, `PageBlock.label` is typed as a required `never` in `packages/form-schema`, so `block.label` still types as `string`. At runtime `apps/api/src/ai/ai.service.ts` and the responses page get `undefined` for a page (for a paged form, that is every top-level block), with no compile error. Revisit when they come back into scope: read names with `blockName`, then change `PageBlock.label` to `label?: never` so the compiler flags any remaining reads. (Phase 7, pages.)
- **The builder's own submit check reads root answers only.** `validateSubmission` in `packages/form-schema` (used by the public submit endpoint behind `/r/<slug>`) loops over the form's root list. It never looks inside pages or groups, so nested questions aren't checked: their `required` is not enforced and their answers are dropped. Groups aren't in `STATIC_TYPES`, so a root-level repeating group's value, an array of instances (contract §12.4), would be stored without any check of its shape, instance count or contents. The `@yourco/forms` renderer validates and strips per instance itself; this gap is only in the builder's hosted form. Revisit when Responses and `/r/<slug>` come back into scope: walk the tree with `walkBlocks`, and validate repeating groups per instance as in contract §12.5. (Repeating groups.)
