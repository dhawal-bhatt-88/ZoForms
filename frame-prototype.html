PrototypeShip to production

From clickable prototype to production

How this HTML walkthrough maps onto the real Frame codebase — structure, stack, and the path to first deploy.

This prototype is a spec you can click

Every screen, flow, and interaction here is intentional. It is a single self-contained HTML file (no build step) meant for walking through the product and aligning the team. The production app re-implements these exact flows as a typed, tested, componentized Next.js + NestJS application. The mapping below keeps design intent 1:1 while swapping the mock layer for real data.

Prototype → production mapping

In this prototypeBecomes in productionNotes
One HTML file, hand-routed via data-navNext.js App Router pages & layoutsEach screen-* → a route segment; app shell → a shared layout.
CSS design tokens & component classesTailwind theme + shadcn/ui componentsPorted 1:1 as design tokens; classes become React components.
Icon <symbol> spritelucide-react icon setSame visual language, tree-shaken.
Static mock data in markupPostgreSQL via Prisma + TanStack QueryServer components fetch; client caches.
Form builder canvas (drag/select)TipTap/ProseMirror + dnd-kit editorBlocks become a versioned JSONB schema.
Publish / embed / domain modalCloudflare SSL-for-SaaS + embed.js bundleReal custom-domain issuance & a tiny runtime.
data-toast confirmationsReal mutations + optimistic toastsNestJS endpoints, BullMQ side-effects.
Auth screens (visual)Auth.js / WorkOS sessions + RBACOrg-scoped authorization on every query.

Recommended project structure (Turborepo monorepo)

frame/
├─ apps/
│  ├─ web/                 # Next.js (App Router) — builder, dashboard, marketing
│  │  ├─ app/(marketing)/  # landing, pricing, templates SEO pages
│  │  ├─ app/(auth)/       # sign up, log in, onboarding
│  │  ├─ app/(app)/        # dashboard, builder, responses, analytics…
│  │  └─ app/r/[slug]/     # public form runtime (rendered form)
│  ├─ api/                 # NestJS — REST /v1, auth, billing, webhooks
│  └─ workers/             # BullMQ consumers — webhooks, email, exports, AI
├─ packages/
│  ├─ ui/                  # shadcn/ui components + design tokens (this kit)
│  ├─ form-schema/         # zod types for the block/JSONB form schema
│  ├─ form-runtime/        # tiny embeddable renderer (embed.js)
│  ├─ db/                  # Prisma schema, migrations, seed
│  └─ config/              # eslint, tsconfig, tailwind preset
├─ infra/                  # Terraform, Dockerfiles, k8s/helm
├─ .github/workflows/      # CI: lint · typecheck · test · e2e · deploy
└─ turbo.json

Path to first deploy

  1. 1 Scaffold the monorepo — Turborepo + the two apps + shared ui package; port these tokens into a Tailwind preset.
  2. 2 Data + auth first — Prisma schema (users, orgs, workspaces, forms, responses), Auth.js sessions, org-scoped guards.
  3. 3 Builder + public runtime — the highest-value slice: block editor writing JSONB, and the cacheable /r/[slug] renderer + submit endpoint.
  4. 4 Responses, billing, integrations — responses table + drawer, Stripe billing, then the webhook/integration worker fabric.
Reusable as-is

Design tokens, component styles, icon set, layouts, copy, and the full IA/flow map transfer directly.

Rebuild typed

Interactions (routing, modals, drag-drop, forms) become React components with state & validation.
